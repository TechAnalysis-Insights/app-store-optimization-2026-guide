# App Store Optimization in 2026 — a reference for the three tools, not a how-to

Apple gives you three separate tools for the product page and they answer three different questions. Mixing them up is the most common way to burn a 90-day test cycle on the wrong question.

## What changed October 5, 2026

- New header asset + search-result asset (image or video), managed via a new Asset Library in App Store Connect.
- A preview tool to check cropping across Dark Mode, devices, and orientations.
- iPhone Duo ships October 23, 2026. Submissions from **April 2027** require iPhone Duo screenshots.

## The three tools

| Tool | What can change | Who sees it | How results are read | Question it answers |
|---|---|---|---|---|
| Product page optimization test | Icon, screenshots, previews — up to 3 treatments | Random share of App Store visitors | Impressions, conversion, improvement, confidence | Which default page version converts better? |
| Custom product page | Screenshots, promo text, previews, keywords, deep link — up to 70 versions | Visitors via unique URL, Apple Ads, or keyword search | Views, downloads, conversion, retention, proceeds vs. default | Does a page built for one audience convert that audience better? |
| Creative assets (Oct 2026) | Header + search-result asset, image or video | Search results and product page browsers | No dedicated metric yet — preview tool checks placement only | How will this visual look on each surface before launch? |

## Rules that are easy to miss

- Treatments in a product page optimization test **cannot be edited once the test starts**.
- Apple recommends waiting for **90% confidence** before acting on a test result.
- Bundle more than one change into a single treatment and you lose the ability to attribute the result to anything specific.
- Guidance on running multiple tests concurrently is inconsistent — plan for one test at a time.
- Name and subtitle are each capped at 30 characters; the keyword field is capped at 100.
- Promotional text (170 characters) is editable without a new app version and does **not** affect search ranking.
- Rating prompts are capped at 3 requests per 365 days.

## Reference cases

- **CBS Sports** — custom page for March Madness mobile web traffic: +20% conversion vs. default.
- **State of Survival** — custom page matched to ad creative: +33% conversion, -14% cost per install.
- **Peak Brain Training** — product page test, brain icon vs. robot icon: +8% conversion over 44 days (clean result, one variable changed).
- **Simply Piano** — product page test, preview video before screenshots: lost to original over 12 days.
- Apple reports referred custom-page visitors average 2.5pp higher conversion vs. 1.6% on default pages — methodology undisclosed, treat as directional.

## A minimal process

1. Baseline in App Analytics before touching anything (impressions, page views, downloads, conversion).
2. Test icon + first screenshot set first — widest reach, and the first 1–3 screenshots are what show in search results.
3. One hypothesis per test. ~4 tests/year is realistic given the 90-day window.
4. Winning page → adapt into custom pages for paid campaigns.
5. Localize metadata (50 languages supported) — screenshots often need different emphasis per market, not just translation.
6. Track retention and proceeds alongside downloads — a download win that doesn't retain isn't a win.
